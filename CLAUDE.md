# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Public 12d Model macro source (12dPL, a C-like language compiled by 12d's `cc4d.exe`). `.4dm` files are macro sources, `.H`/`.h`/`.4d` are includable headers, and `.4do` files are compiled macros that are run inside the 12d Model application. There is no lint step and no automated test runner. "Testing" means compiling, then running the `.4do` in 12d.

## Build

The toolchain is set up for **12d Model v15**. The compiler path `C:/Program Files/12d/12dmodel/15.00/nt.x64/cc4d.exe` is hardcoded in `build/Make_4do_From_4dm.bat`, in the prototypes task in `.vscode/tasks.json`, and in the `set_ups` include path in `.vscode/c_cpp_properties.json`. Change all three when targeting a different version. `build/Make_4do_From_4dm_v14.bat` points at v14.00.

- Compile one macro (the VS Code default build, Ctrl+Shift+B, runs this on the focused file):
  `build\Make_4do_From_4dm.bat "C:\GitHub\12dPub\src\...\NAME.4dm"`
- Direct compile without the bat: `cc4d.exe NAME.4dm -allow_old_calls`. This skips the bat's `CPATH` setup and version defines, so prefer the bat.
- Regenerate the prototypes file used for IntelliSense: `cc4d.exe -list include/prototypesv15.4dm` (VS Code task "12dPL: Regenerate prototypes file (v15)")

Includes are resolved through the **`CPATH`** environment variable (cc4d also accepts `CPLUS_INCLUDE_PATH`). Separate multiple paths with a Unix-style `:`, not `;`. The build bats put `<repo>\include` at the front of any existing `CPATH` for the duration of the compile, so a fresh clone needs no setup. A personal `CPATH`, such as one that also points at another repo's include folder, still gets searched after it. A missing header prints `file.4dm:1: X.H: file not found` but doesn't count as an error. Watch for "not defined" errors that follow it. This is why sources write `#include "mashy_lib_files.H"` and `#include "12d/set_ups.h"` with no relative path.

What the build bat does:
- It expects the source to be under `\src\`. It derives the repo root by splitting the path at `\src\`, so a file outside `src/` gets a wrong `bin` path.
- It passes the compiler version to the macro as the defines `QUOTED_CC4D_VERSION_DATA`, `MACRO_VERSION_4D`, `MACRO_LAST_OPCODE_4D` and `MACRO_LAST_LIBRARY_CODE_4D`. Library code such as the about panel can show these.
- It copies the `.4do` to `bin/` (and to `bin/_macro_hot_off_the_press.4do`, which is gitignored) and writes a matching `bin/NAME.json` with compile metadata. Filenames containing `test` or `mashy_lib` are compiled but **not** copied to `bin/`.
- It passes `-log` so compiler errors land in `NAME.4dl` next to the source (gitignored), then types that file so the VS Code problem matcher still sees them.
- It checks cc4d's exit code. cc4d deletes the existing `.4do` when a compile fails, so on failure the bat leaves `bin/` and its `.json` untouched (the last good build stays) and exits with 1.

All VS Code compile tasks call the bat, and there's no `launch.json`. The `tasks.json` problem matchers parse cc4d errors of the form `"file", line N.C: error: message`, and report `file:N: X.H: file not found` lines as warnings.

## Layout and architecture

- `src/<Theme>/<Macro Name>/PREFIX-Name.4dm`: standalone macros, each with a `void main()`. The prefix names the theme (`FILES-`, `VIEW-`, `MACRO-`, `CODING_`). Compiled `.4do` files under `src/` are gitignored. The committed copies live in `bin/`.
- `bin/`: committed compiled `.4do` files plus their `.json` build info. They are regenerated by the build, so don't hand-edit them.
- `test/`: experimental and prototype macros (programmatic menus and panels). Their `.4do` files are committed next to the source.
- `include/mashy_lib_*.H`: the author's reusable library. It is grouped by theme (widgets, panels, files, XML, super alignments, TINs, geometry, sorting, and so on). Each header has an include guard such as `#ifndef mashy_lib_files_H_included`, and headers include each other freely.
- `include/12d/`: headers taken from the 12d forums (standard library, `set_ups.h`, and others). Include them as `"12d/..."`.
- `include/prototypesv15.4dm`: generated list of API prototypes, used only for editor highlighting and IntelliSense. VS Code maps `*.4dm`/`*.h`/`*.4d` to C++ with the Tag Parser engine.

### Common macro pattern

Most macros build a 12d `Panel` from widgets (`Create_panel`, `Create_*_box`, `append`, and so on) and then run an event loop that dispatches on `cmd` strings. An "About" button calls `manage_about_panel()` from `mashy_lib_about_panel.H`. A macro customises the About panel by defining `ABOUT_PANEL_DATA_INCLUDED` and the globals `about_macro_by`, `about_macro_for`, `about_macro_description` and `about_macro_changes` **before** it includes that header. Otherwise the header supplies defaults. `mashy_lib_panel_defaults.H` and `mashy_lib_widgets_standard.H` supply the shared panel and widget boilerplate. Files ending in `-old` are superseded versions kept for reference.
